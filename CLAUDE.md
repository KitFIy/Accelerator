# Axisec — записка следующей сессии

Axisec — шлюз между ИИ-агентом и инфраструктурой: проверяет вызовы инструментов
детерминированно (SQL по AST, схемы аргументов, DLP) и блокирует запрещённое политикой.
Студенческий проект Акселератора РТУ МИРЭА, Demo Day 30.11.2026, выступление 5 минут.
MVP 0.1 работает, презентации и паспорт готовы. Запуск и состав — в `README.md`.

## Правила проекта

- **Цифра на слайде имеет происхождение.** Измеренная сначала попадает в
  `docs/02_mvp_results.md`, взятая из источника — в `docs/01_research_factcheck.md`,
  и только потом на слайд. Цифры без происхождения из исходных материалов уже убраны.
- **Презентации и паспорт собираются скриптами.** Правка идёт в `deck/build_decks.py` и
  `deck/build_passport.py`, затем пересборка. Текст выступления живёт в
  `deliverables/speech_5min.md` между метками `<!-- slide: -->` и попадает в заметки слайдов.
  После пересборки отрендери слайды в картинки и посмотри их: переполнение текста видно
  только так. В шаблоне шрифт Helvetica Neue, здесь он подменяется, оставляй запас по ширине.
- **`source/` — оригиналы команды, только чтение.**
- **Ущерб считается по состоянию демо-мира** (`World.harms`), а не по решениям шлюза.
  Новая атака в `scenarios.yaml` обязана наносить ущерб без шлюза — это проверяет
  `test_red_team_suite`. Новое правило движка получает случаи в `corpus.yaml`: и блокируемые,
  и легитимные.
- **Имитатор модели намеренно послушный** (`axisec/demo/mock_llm.py`): выполняет любую
  найденную инструкцию. На реальных моделях шлюз ещё не проверялся.
- **Единственная ветка репозитория — она же production для Vercel.** Пуш запускает деплой.
  В деплой идут только код и политики (`.vercelignore`): в документах команды личные контакты.
- Docker Hub из песочницы отдаёт 429. Сборка образа:
  `--build-arg PYTHON_IMAGE=public.ecr.aws/docker/library/python:3.12-slim`.

   Мотов; после ответа один вариант должен стоять в паспорте, обеих презентациях и тексте
   выступления. Ещё: SOM (сейчас 11–16 млн ₽ вместо исходных 45), есть ли подтверждения
   спроса, обязателен ли шаблон, будет ли живое демо, есть ли ключи GigaChat или YandexGPT.
3. Название «Axisec» на совпадение с чужими товарными знаками не проверялось.

## До Demo Day, по порядку

1. Закрыть пункты 1 и 2 выше.
2. **Реальные модели.** Прогнать 14 сценариев через шлюз на GigaChat и YandexGPT
   (`AXISEC_LLM_UPSTREAM`, `AXISEC_LLM_API_KEY`). Для GigaChat нужен адаптер: получение
   токена и формат `functions` в запросе (в ответе `function_call` шлюз уже понимает).
   Готово, когда в `docs/02_mvp_results.md` есть таблица «сценарий × модель: ущерб без шлюза
   и через шлюз», а слайд с результатами обновлён.
3. **Нагрузка.** Замер с параллельными клиентами (50–200): p50, p95, p99 и запросов в секунду
   в `bench/` и `docs/02_mvp_results.md`. Сейчас замер только последовательный.
4. Прогон выступления с командой: уложиться в 5 минут, правки по итогам.

## Развитие продукта после защиты, по приоритету

1. **Авторизация.** Дашборд и API шлюза открыты всем (включая очистку журнала). Без этого
   нельзя идти ни в один пилот.
2. **Режим наблюдения и черновик политики.** Шлюз только пишет в журнал, а политика
   генерируется из `tools/list` агента. Это снимает главный барьер внедрения.
3. **Подтверждение человеком** для действий выше порога — ответ на «атака в рамках разрешённого».
4. Настоящая потоковая передача ответов модели и серверные потоки MCP.
5. Политики по ролям: разные агенты и пользователи — разные права.
6. Новые разборщики: команды оболочки, пути к файлам; корпуса для PostgreSQL и MySQL.
7. Экспорт в SIEM, метрики, запуск на Astra Linux, регистрация программы, реестр ПО.

Позиция на рынке: контроль действий агента (в России там два продукта из восемнадцати),
отличие — глубина разбора SQL и стенд, который показывает реальный ущерб «до и после».
Сертификата ФСТЭК нет, поэтому первые пилоты — в коммерческих компаниях или через интегратора.
